# v2 Features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add 7 user-requested features to the White Horse Reservoir campaign site: seed news items from existing data; collapsible distant-future section on facts page; action cross-links on facts and actions pages; "Generate letter" buttons; ZIP letter pack download; letters-page note; action deadlines.

**Architecture:** All changes are to data files (JSON), Jinja2 templates, Python build code, and one client-side JS file. No new pages. No server-side changes. The static site generator reads JSON/CSV from `data/`, renders to `docs/` via Jinja2 templates, and GitHub Pages serves `docs/`.

**Tech Stack:** Python 3.11 + Jinja2 (generator), vanilla JS (client-side), JSZip 3.10.1 (cdnjs.cloudflare.com), pytest 7.x

**Spec:** This plan is self-contained (no separate spec file). Each feature is derived from the v1-build design documents and the user's stated requirements.

## Global Constraints

- No paid APIs, no server-side code, no new Python dependencies beyond requirements.txt
- User-agent for any fetch: `WHReservoir/1.0 (+https://github.com/davidmcneil99/white-horse-reservoir)`
- Store only headline, date, summary (max 300 chars), and URL for news items — never full article text
- Source files at `E:\reservoir` are READ ONLY — never edit them
- All JS must work without a lookup result (graceful degradation)
- Postcode lookup is optional; ZIP download uses whatever details are available (NOT_FOUND for missing fields)
- `ai_generated: false` on all hand-seeded news items
- JSZip version: exactly `3.10.1` from `cdnjs.cloudflare.com`
- Distant-future threshold: timeline item year >= `datetime.today().year + 3` (i.e. >= 2029 as of build date 2026-11-01)
- Tests: `python -m pytest tests/ -q` must pass (28 tests baseline; add new tests for T3 changes)

## Review Focus

- Collapsible `<details>` must be closed by default (`open` attribute absent) and contain ALL items >= threshold year, none below it
- ZIP file must contain one `.txt` file per letter type (10 files) even when no postcode lookup was done (NOT_FOUND placeholders remain)
- Letter pre-selection via URL hash (`letters.html#mp`) must work when JS loads after hash is set (use `DOMContentLoaded` or check `readyState`)
- `<details>` summary text must describe contents ("Future milestones (2029 and beyond)")
- Sorting actions by deadline must not change the timing-group structure; within each group, actions without a deadline appear last, in their original order
