# White Horse Reservoir Campaign App: V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy a static campaign web app on GitHub Pages that lets any resident near the proposed White Horse Reservoir find out what is happening, look up their representatives by postcode, and send pre-filled letters to officials -- all updated automatically by a daily GitHub Actions pipeline.

**Architecture:** A Python generator reads data from JSON/CSV files and Jinja2 templates, applies a corrections overlay from `data/overrides.json`, and writes static HTML to `docs/`. A separate fetcher (`generator/fetch.py`) polls RSS feeds, JSON APIs, and monitored pages, writing new items to `data/fetched/`. GitHub Actions runs both daily and deploys `docs/` to GitHub Pages. All location lookup and letter rendering is client-side JavaScript using postcodes.io; no server is needed.

**Tech Stack:** Python 3.11, Jinja2, feedparser, requests; HTML5/CSS3/vanilla JS; Leaflet 1.9.4 + OpenStreetMap; postcodes.io (free, no key); GitHub Pages; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-01-white-horse-reservoir-design.md`

## Global Constraints

- Python 3.11 minimum; no third-party packages beyond: jinja2, feedparser, requests, pytest (dev only)
- UK English throughout; no em dashes; no emojis in site copy
- Mobile-first CSS; WCAG 2.2 AA target
- Zero running cost; no paid APIs or services
- `data/white-horse-reservoir-sources.json` is the master dataset: do not modify it; read it only
- `data/overrides.json` is the only file used to correct published items
- Corrected items must show a visible note: "Corrected on [date]: [note]"
- All corrections appear on `corrections.html`
- Fetch politely: respect robots.txt; no bot user-agent strings
- Store only headline, date, summary (max 300 chars), and URL for news items -- never full article text
- Representative data lives in JSON/CSV, never hardcoded in templates or scripts
- Secretary of State field in letter templates must be a data field (currently Emma Reynolds MP, emma.reynolds.mp@parliament.uk), not hardcoded copy
- `docs/` is the GitHub Pages root; never commit generated files to `main` manually -- the Action does it

## Review Focus

1. **postcode with no match in lookup-data.json** -- postcodes.io may return a ward or constituency name that does not match any row in the CSV. Expected: graceful "no match found" message with the raw postcodes.io values shown so the user can identify their area manually. Add to Task 6.
2. **RSS feed returns 200 but empty item list** -- West Hanney's feeds are valid but always empty. Expected: fetcher logs a warning, writes nothing to fetched/, does not error. Add to Task 8.
3. **Source returns HTTP 403 or robots.txt blocks crawling** -- OCC ModernGov, Oxford Mail. Expected: fetcher logs a warning, skips the source, pipeline continues. Add to Task 8.
4. **overrides.json references an item_id that does not exist** -- Expected: generator logs a warning and skips the override; it does not crash or silently swallow it. Add to Task 3.
5. **Letter template placeholder left unfilled** -- if postcodes.io lookup fails to find an MP, the letter must not show `{{mp_name}}` raw. Expected: unfilled placeholders render as `[not found -- please fill in]`. Add to Task 7.

- [ ] **Step 3: Implement generator/utils.py**

`format_date(date_str, precision)`: uses Python `datetime.strptime` for day/month precision; returns year string directly. Day format: `"%-d %B %Y"` (Linux) or `"%#d %B %Y"` (Windows).

`truncate(text, max_chars)`: if `len(text) > max_chars`, return `text[:max_chars] + "..."`, else return `text`.

- [ ] **Step 4: Implement generator/overrides.py**

`apply_overrides(items, overrides, item_type)`:
- Filter overrides to those where `override["item_type"] == item_type`.
- For each matching override, find the item by `item["id"] == override["item_id"]`.
- If not found: log a warning (`logging.warning(f"Override references unknown id {override['item_id']}")`).
- If found: update `item[override["field"]] = override["new_value"]`; set `item["_corrected_on"] = override["corrected_on"]`; set `item["_correction_note"] = override["correction_note"]`.
- Return the mutated list.

```js
window.WHRLookup = (function() {
  async function lookup(postcode) {
    // 1. Fetch postcodes.io
    // 2. Load lookup-data.json (cached after first load)
    // 3. Match constituency -> MP; ward (with aliases) -> district councillors;
    //    county_electoral_division -> county councillors; parish -> parish council
    // 4. If no match for any field: include field in result with null value
    // 5. Return { mp, countyCouncillors, districtCouncillors, parish,
    //             accessPoints: all access points (no lat/lon filter in v1),
    //             raw: postcodes.io result }
  }
  async function renderWidget(containerId) {
    // Render input + button into container; on submit call lookup() and render results
    // If postcodes.io returns 404: show "Postcode not found"
    // If lookup returns no match for a field: show the raw postcodes.io value with note "We could not match this automatically"
    // Results include: area summary, councillors with email links, access points table subset
  }
  return { lookup, renderWidget };
})();
```

- [ ] **Step 3: Implement generator/fetch.py**

`fetch_rss(url, source_name)`:
- Calls `feedparser.parse(url)`.
- If status 403 or no entries: log warning, return `[]`.
- For each entry: extract title (truncate 120 chars), link, published date, and summary (truncate 300 chars). Return list of new_item dicts.

`fetch_json_api(url, source_name, title_field, url_field, date_field, summary_field)`:
- Calls `requests.get(url, headers={"User-Agent": "WHReservoir/1.0 (+https://github.com/davidmcneil99/white-horse-reservoir)"}, timeout=15)`.
- If not ok: log warning, return `[]`.
- Parses JSON, extracts items using field name params.
- Returns list of new_item dicts.

`detect_page_change(url, old_hashes)`:
- Fetches page with same User-Agent header.
- If not ok: log warning, return `(False, old_hashes.get(url, ""))`.
- Compute SHA-256 of response text.
- Compare to `old_hashes.get(url)`. Return `(changed: bool, new_hash: str)`.

`load_sources()`:
- Reads `data/national-and-other-sources.csv` and also reads `data/white-horse-reservoir-sources.json` for local council feeds.
- Returns list of source dicts with fields: `name`, `type` (rss|json_api|page_change), `url`, `notes`.

`fetch_all(sources, hashes)`:
- Dispatches each source to the appropriate fetch function.
- For page-change sources: records change in news_items if changed, with title "Page change detected: {source_name}" and URL.
- Deduplicates against existing items (by URL).
- Returns `(new_items, updated_hashes)`.

CLI entrypoint at bottom of file:
```python
if __name__ == "__main__":
    import json
    from pathlib import Path
    sources = load_sources()
    hashes = json.loads(Path("data/fetched/page_hashes.json").read_text())
    existing = json.loads(Path("data/fetched/news_items.json").read_text())
    new_items, new_hashes = fetch_all(sources, hashes)
    # Deduplicate against existing
    existing_urls = {i["url"] for i in existing}
    to_add = [i for i in new_items if i["url"] not in existing_urls]
    all_items = (to_add + existing)[:500]  # max 500, newest first
    Path("data/fetched/news_items.json").write_text(json.dumps(all_items, indent=2))
    Path("data/fetched/page_hashes.json").write_text(json.dumps(new_hashes, indent=2))
    print(f"Fetched {len(to_add)} new items")
```
